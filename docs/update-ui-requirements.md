# 更新UI 要件定義（初版）

## 1. 目的
既存の静的サイト（GitHub Pages運用）を、HTML直接編集なしで更新できるようにする。
対象は以下の3カテゴリ。

1. News（最優先）
2. 資料（PDF/画像を含む）
3. メンバー

## 2. 利用者・権限
- 利用者: 管理者1名（サイト管理者本人）
- 権限モデル: 単一管理者
- 認証: パスワード認証を必須とする

## 3. 更新対象データ

### 3.1 News
- 項目
  - 日付
  - タイトル
  - 本文
  - リンク（任意）
- 操作
  - 追加
  - 編集
  - 削除
  - 並び順制御（基本は日付降順）
- ワークフロー
  - 下書き保存
  - プレビュー確認
  - 公開

### 3.2 資料
- 対象
  - PDF
  - 画像
- 項目
  - タイトル
  - 説明（任意）
  - 公開日
  - 添付ファイル（1件以上を想定）
  - リンク（任意）
- 操作
  - 追加
  - 編集
  - 削除
  - アップロード
- ワークフロー
  - 下書き保存
  - プレビュー確認
  - 公開

### 3.3 メンバー
- 項目
  - 氏名
  - 役職・区分
  - 紹介本文
  - リンク（任意）
  - 画像（任意）
- 操作
  - 追加
  - 編集
  - 削除
  - 表示順変更
- ワークフロー
  - 下書き保存
  - プレビュー確認
  - 公開

## 4. 非機能要件
- ホスティング: GitHub Pages
- デバイス: PC優先（スマホ対応は低優先、可能なら管理画面をレスポンシブ化）
- ファイルサイズ制限: 現時点では特に上限なし
- 可用性: GitHub Pages標準範囲

## 5. 履歴要件
- 要件: 変更履歴を保存する
- 最低限必要な記録
  - 変更日時
  - 対象（News / 資料 / メンバー）
  - 操作種別（追加/編集/削除/公開）
  - 変更概要

## 6. 想定実装方式（推奨）
GitHub Pages で「ログイン」「下書き→公開」「アップロード」「履歴保存」を成立させるため、
**GitHub + Headless CMS（例: Decap CMS）構成**を推奨する。

- コンテンツ本体: Git管理（Markdown / JSON / YAML）
- 画像/PDF: リポジトリ内に保存
- 認証: GitHub OAuth（管理者アカウントのみ許可）
- ワークフロー: Editorial Workflow（Draft / In Review / Ready / Publish）
- 履歴: Gitコミット履歴（必要なら changelog 自動生成を追加）

## 7. 受け入れ条件（初版）
1. 管理画面にログインできること
2. News を下書き→プレビュー→公開できること
3. 資料に PDF/画像をアップロードして公開できること
4. メンバー情報を追加/編集/削除して公開できること
5. 変更履歴が Git 上で追跡できること
6. 公開後、GitHub Pages に反映されること
